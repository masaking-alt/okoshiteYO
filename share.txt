コア実装イメージ（最小サンプル）
================

tsx

Copy code

```tsx
// App.tsx（TypeScript想定）
import React, { useEffect } from 'react';
import { View, Text, Button, Platform } from 'react-native';
import notifee, {
  AndroidImportance,
  TimestampTrigger,
  TriggerType,
  AndroidAlarmManager
} from '@notifee/react-native';

async function ensurePermissions() {
  // iOS: 通知許可
  // Android: POST_NOTIFICATIONS(API33+), exact alarmは後述
  await notifee.requestPermission();
}

async function createChannel() {
  if (Platform.OS === 'android') {
    await notifee.createChannel({
      id: 'alarm',
      name: 'Alarm',
      sound: 'alarm',          // android/app/src/main/res/raw/alarm.wav 等
      vibration: true,
      importance: AndroidImportance.HIGH,
      bypassDnd: true,         // DNDを一部バイパス（端末設定依存）
    });
  }
}

export async function scheduleAlarm(timestampMs: number) {
  // Androidで正確なアラームをねらう設定
  let alarmManager: AndroidAlarmManager | undefined = undefined;
  if (Platform.OS === 'android') {
    alarmManager = {
      allowWhileIdle: true,
      // exact: true は Notifee 側で適用（端末/権限次第でフォールバック必要）
    };
  }

  const trigger: TimestampTrigger = {
    type: TriggerType.TIMESTAMP,
    timestamp: timestampMs, // 未来のUNIXミリ秒
    alarmManager,           // Androidのみ
    repeatFrequency: undefined, // 繰り返しは自前ロジック推奨（曜日指定など）
  };

  await notifee.createTriggerNotification(
    {
      title: '起床時間！',
      body: 'スヌーズしますか？',
      android: {
        channelId: 'alarm',
        sound: 'alarm', // res/raw に配置
        onlyAlertOnce: false,
        pressAction: { id: 'default' },
        actions: [
          { title: 'スヌーズ(5分)', pressAction: { id: 'SNOOZE_5' } },
          { title: '停止', pressAction: { id: 'STOP' } },
        ],
        // fullScreenAction でフルスクリーン起動（要端末設定/OSバージョン依存）
        fullScreenAction: { id: 'FULL_SCREEN' },
      },
      ios: {
        sound: 'alarm.caf', // iOSはBundleに同梱・30秒以内
        categoryId: 'ALARM_CATEGORY', // アクション用カテゴリ
      },
    },
    trigger
  );
}

export default function App() {
  useEffect(() => {
    (async () => {
      await ensurePermissions();
      await createChannel();

      // 通知アクションのハンドリング（スヌーズ等）
      return notifee.onForegroundEvent(async ({ type, detail }) => {
        if (detail.pressAction?.id === 'SNOOZE_5') {
          const in5min = Date.now() + 5 * 60 * 1000;
          await scheduleAlarm(in5min);
        }
      });
    })();
  }, []);

  const setAlarmIn1Min = async () => {
    await scheduleAlarm(Date.now() + 60 * 1000);
  };

  return (
    <View style={{ flex:1, justifyContent:'center', alignItems:'center', gap:16 }}>
      <Text>React Native 目覚まし</Text>
      <Button title="1分後にアラーム" onPress={setAlarmIn1Min} />
    </View>
  );
}
```

プラットフォーム別の要点
============

Android
-------

*   **精密アラーム（Exact Alarm）**

    *   Android 12+ では「正確なアラーム」に制約。`AndroidManifest.xml` に

xml Copy code   ```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
```  
を宣言。初回起動後、端末の設定でユーザーに許可してもらう導線や、**許可されない場合のフォールバック**（`setAndAllowWhileIdle` → 通知トリガ + 若干の遅延許容）を用意。

*   **Doze/最適化**

    *   `allowWhileIdle: true` を指定。端末の電池最適化で遅延する可能性はある。重要アプリとしての説明UIを用意。

*   **再起動復元**

    *   `RECEIVE_BOOT_COMPLETED` を宣言し、ブート後にアラームを再スケジュール。

*   **チャンネル**

    *   大音量・バイブ用に `importance=HIGH`、`bypassDnd=true`（端末設定依存）を設定。

iOS
---

*   **通知音**

    *   `alarm.caf` など30秒以内の音源をバンドル。サイレントや集中モード中は**基本的に鳴らない**（Apple純正「時計」だけ特権的）。

    *   「Critical Alerts」は申請・審査が必要（多くの一般アプリは通らない）。

*   **繰り返し**

    *   曜日ごとの繰り返しは、**次回分だけを自前で再スケジュール**（日付ずれ/DST対応のためにも安全）。

*   **通知アクション**

    *   `UNNotificationAction`/`UNNotificationCategory` を設定してスヌーズ等を実現。

⚙️ 2. 仕組みの違い
------------

### React Native

*   JSで書いたUIを、ランタイム（Bridge）を通して**ネイティブUIに変換**して表示。

*   つまり「内部はネイティブ」だけど、ロジックはJSで動く。

*   クロスプラットフォームだけど、**パフォーマンスは純ネイティブより少し劣る**。

*   UIも共通化しやすく、Webエンジニアが参入しやすい。

### Kotlin（Androidネイティブ）

*   Android OSが直接実行する**ネイティブコード**（JVMバイトコード）。

*   OSの機能（カメラ、通知、Bluetooth、バックグラウンド処理など）を**フルに使える**。

*   Google公式推奨。将来性・安定性が高い。

*   iOS用に書き換えるならSwiftなど**別言語が必要**。

結論（おすすめ構成）
==========

*   **共通層（JS/TS）：** 画面、設定、アラーム一覧、状態管理（Redux/Zustand など）

*   **ブリッジAPI（Native Module / TurboModule）：**`AlarmEngine`

    *   `addAlarm({time, days, label})`

    *   `enableAlarm(id) / disableAlarm(id)`

    *   `snooze(id, minutes)`

    *   イベント: `ALARM_FIRED`, `ALARM_STOPPED`

*   **通知・鳴動ライブラリ（共通）：****@notifee/react-native**（ローカル通知＆アクション）

*   **Android（Kotlin）：**`AlarmManager`（正確なアラーム）, `BroadcastReceiver`（BOOT復元）, **ForegroundService**（鳴動・ループ再生・フルスクリーン起動）

*   **iOS（Swift）：**`UNUserNotificationCenter`（ローカル通知）, `UNNotificationCategory/Action`（スヌーズ）, **AVAudioSession**（バンドル音30秒まで）。※DND突破は不可（Critical Alertsは原則使えない）

* * *

なぜこうする？
=======

*   **React Nativeだけ**だと、バックグラウンドや再起動復元、正確な発火などで限界が出やすい

*   **ネイティブ実装**だと、

    *   Android: `SCHEDULE_EXACT_ALARM` や Doze まわりに正面から対応できる

    *   iOS: ローカル通知の正式APIを直接使い、通知アクション→再スケジュールが確実

* * *

役割分担の詳細
=======

共通（JS/TS）
---------

*   DB：SQLite/Realm などでアラーム定義を保持（UTC保持→表示はローカル）

*   次回発火日時の算出（曜日繰り返し・祝日スキップ等）

*   画面：アラーム一覧、作成/編集、許可ガイド（通知権限・電池最適化除外など）

Android（Kotlin）
---------------

*   `AlarmManager.setExactAndAllowWhileIdle(...)` でスケジュール

*   受信：`BroadcastReceiver` → **ForegroundService** 起動

*   鳴動：Service内で `MediaPlayer` ループ再生 + `FULL_SCREEN_INTENT` 通知

*   再起動復元：`RECEIVE_BOOT_COMPLETED` でDBから再スケジュール

*   権限：

    *   `POST_NOTIFICATIONS`

    *   `SCHEDULE_EXACT_ALARM`（設定画面誘導あり）

*   フォールバック：

    *   許可なし/Dozeで遅延 → Notifeeのタイムスタンプトリガ＋`allowWhileIdle`で“ほぼ正確”に

iOS（Swift）
----------

*   `UNCalendarNotificationTrigger` or `UNTimeIntervalNotificationTrigger` で**次回分のみ**予約（DST/ズレ対策）

*   通知アクション（SNOOZE/STOP）で再スケジュール

*   音：`UNNotificationSound(named: ...)`（~30秒）。長時間ループは**不可**（前面起動が必要）

*   注意：サイレント/集中モード中は**原則鳴らない**（公式時計アプリだけ特権的）。仕様としてユーザーに明記

* * *

実装スタックまとめ
=========

*   **@notifee/react-native**：ローカル通知・アクション（共通）

*   **react-native-permissions**：権限リクエスト＆設定画面導線

*   **Native Modules**：`AlarmEngine`（Kotlin/Swiftで実装し、RNに公開）

*   **DB**：`react-native-sqlite-storage` / `realm` / `watermelondb` いずれか

* * *

典型フロー（擬似コード）
============

1.   ユーザーがUIでアラーム作成

2.   JSで**次回発火日時**を計算 → `AlarmEngine.addAlarm(nextFireAt, meta)`

3.   OSが発火 →

    *   Android: Receiver → ForegroundService で音ループ + フルスクリーン

    *   iOS: ローカル通知（バンドル音）＋通知アクション

4.   スヌーズ押下 → `AlarmEngine.snooze(id, 5)`（nextFireAt計算→再スケジュール）

5.   停止押下 → 鳴動停止 + **次回定義があるなら**次の曜日分をJSが再計算し予約

6.   端末再起動/時刻変更/タイムゾーン変更イベント → 全アラーム再スケジュール

* * *

これだけは避ける
========

*   **サーバープッシュ（FCM/APNs）でアラーム**：オフラインや遅延があり、目覚まし用途に不適

*   **JSだけで常駐タイマー**：OSが止める（省電力）

* * *

最短の着工手順
=======

1.   RNプロジェクト作成（TS）

2.   Notifee導入（権限・チャンネル設定）

3.   **AndroidのForegroundService**を先に作る（確実に鳴らす土台）

4.   `AlarmEngine` ブリッジの最小APIを切る（`scheduleOnce(ts)`, `cancel(id)` から）

5.   UIとつないで「1分後に鳴る」→「スヌーズ」→「再起動復元」へ拡張

6.   iOSのローカル通知を追加（30秒音・アクション）

🟩 Android のネイティブAPI（Kotlin / Java）
===================================

### 1. `AlarmManager`

*   アラームをOSレベルでスケジュールするAPI。

*   スリープ中でも端末が起きてイベントを発火できる。

*   「正確なアラーム」を使うには Android 12 以降で `SCHEDULE_EXACT_ALARM` 権限が必要。

kotlin

Copy code

```kotlin
val alarmManager = context.getSystemService(Context.ALARM_SERVICE) as AlarmManager
val intent = Intent(context, AlarmReceiver::class.java)
val pendingIntent = PendingIntent.getBroadcast(context, 0, intent, PendingIntent.FLAG_UPDATE_CURRENT)

val triggerAtMillis = System.currentTimeMillis() + 60 * 1000  // 1分後
alarmManager.setExactAndAllowWhileIdle(
    AlarmManager.RTC_WAKEUP,
    triggerAtMillis,
    pendingIntent
)
```

*   `RTC_WAKEUP`：スリープ中でも起こして実行

*   `setExactAndAllowWhileIdle`：Dozeモード中でも正確に実行

* * *

### 2. `BroadcastReceiver`

*   `AlarmManager`からの通知を受け取る部分。

*   通常はここで音を鳴らすServiceを起動する。

kotlin

Copy code

```kotlin
class AlarmReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val serviceIntent = Intent(context, AlarmService::class.java)
        ContextCompat.startForegroundService(context, serviceIntent)
    }
}
```

* * *

### 3. `ForegroundService`

*   長時間の処理や通知音ループに使う。

*   通知バーに常駐させる必要がある。

kotlin

Copy code

```kotlin
class AlarmService : Service() {
    private lateinit var player: MediaPlayer

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        player = MediaPlayer.create(this, R.raw.alarm_sound)
        player.isLooping = true
        player.start()

        val notification = NotificationCompat.Builder(this, "alarm")
            .setContentTitle("アラーム")
            .setContentText("起きる時間です！")
            .setSmallIcon(R.drawable.ic_alarm)
            .setPriority(NotificationCompat.PRIORITY_HIGH)
            .build()

        startForeground(1, notification)
        return START_STICKY
    }

    override fun onDestroy() {
        player.stop()
        super.onDestroy()
    }
}
```

🟦 iOS のネイティブAPI（Swift）
=======================

### 1. `UNUserNotificationCenter`

*   ローカル通知の登録・管理を行う中核API。

*   通知トリガーを「日時」や「間隔」で指定できる。

swift

Copy code

```swift
let center = UNUserNotificationCenter.current()
let content = UNMutableNotificationContent()
content.title = "アラーム"
content.body = "起きる時間です！"
content.sound = UNNotificationSound(named: UNNotificationSoundName("alarm.caf"))

let date = Date().addingTimeInterval(60) // 1分後
let trigger = UNTimeIntervalNotificationTrigger(timeInterval: 60, repeats: false)
let request = UNNotificationRequest(identifier: "alarm1", content: content, trigger: trigger)

center.add(request)
```

* * *

### 2. `UNCalendarNotificationTrigger`

*   曜日・時刻など、カレンダー形式でアラームを指定する。

swift

Copy code

```swift
var dateComponents = DateComponents()
dateComponents.hour = 7
dateComponents.minute = 0
let trigger = UNCalendarNotificationTrigger(dateMatching: dateComponents, repeats: true)
```

* * *

### 3. 通知アクション（スヌーズなど）

*   通知にボタンを付けて、ユーザー操作に応答できる。

swift

Copy code

```swift
let snoozeAction = UNNotificationAction(identifier: "SNOOZE", title: "スヌーズ", options: [])
let stopAction = UNNotificationAction(identifier: "STOP", title: "停止", options: [.destructive])
let category = UNNotificationCategory(identifier: "ALARM_CATEGORY",
                                      actions: [snoozeAction, stopAction],
                                      intentIdentifiers: [], options: [])
UNUserNotificationCenter.current().setNotificationCategories([category])
```

→ 通知を登録するときに `content.categoryIdentifier = "ALARM_CATEGORY"` を指定。

* * *

### 4. `AVAudioSession` / `AVAudioPlayer`

*   音声を鳴らすAPI。

*   通知音は30秒以内・サイレントモード中は鳴らない制約あり。

swift

Copy code

```swift
let url = Bundle.main.url(forResource: "alarm", withExtension: "caf")!
let player = try! AVAudioPlayer(contentsOf: url)
player.play()
```

* * *

### ❌ iOSの制約

*   バックグラウンドで長時間鳴らすのは不可

*   サイレントモードや集中モードでは音が出ない（純正時計アプリのみ例外）

*   正確な「時刻アラーム」はローカル通知で代用するしかない

* * *

🧠 まとめ：ネイティブAPIの位置づけ
====================

| 機能 | Android | iOS |
| --- | --- | --- |
| アラームスケジュール | `AlarmManager` | `UNCalendarNotificationTrigger` |
| 音の再生 | `MediaPlayer` / `Service` | `AVAudioPlayer` |
| 通知制御 | `NotificationManager` | `UNUserNotificationCenter` |
| スヌーズ・停止ボタン | 通知アクション | 通知アクション |
| 端末再起動後復元 | 可能（`BOOT_COMPLETED`） | 不可（アプリ再起動時に再登録必要） |
| バックグラウンド鳴動 | 可（ForegroundService） | 制限あり（通知音のみ） |

* * *

つまり：

> 🔹 Android：OSレベルの「正確なアラーム＋バックグラウンド音再生」が可能。
> 
>  🔹 iOS：通知トリガーで“それっぽく”実現するが、純正レベルの制御は不可。

🔗 どうやって連携するの？
==============

React Nativeでは **「ネイティブモジュール（Native Module）」** という仕組みを使って、

 JS ↔ Kotlin / Swift を橋渡しする。

* * *

例）React Native ↔ Kotlin
-----------------------

### 1. JS側から呼ぶ

tsx

Copy code

```tsx
import { NativeModules } from 'react-native';
const { AlarmEngine } = NativeModules;

AlarmEngine.scheduleAlarm('2025-11-07T07:00:00Z');
```

### 2. Kotlin側（Android/app/src/main/java/.../AlarmEngineModule.kt）

kotlin

Copy code

```kotlin
package com.alarmapp

import android.app.AlarmManager
import android.app.PendingIntent
import android.content.Context
import android.content.Intent
import com.facebook.react.bridge.*

class AlarmEngineModule(private val reactContext: ReactApplicationContext)
  : ReactContextBaseJavaModule(reactContext) {

  override fun getName() = "AlarmEngine"

  @ReactMethod
  fun scheduleAlarm(datetime: String) {
    val alarmTime = /* datetimeをパースしてUNIX時間に変換 */
    val am = reactContext.getSystemService(Context.ALARM_SERVICE) as AlarmManager
    val intent = Intent(reactContext, AlarmReceiver::class.java)
    val pi = PendingIntent.getBroadcast(reactContext, 0, intent, PendingIntent.FLAG_IMMUTABLE)
    am.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, alarmTime, pi)
  }
}
```
